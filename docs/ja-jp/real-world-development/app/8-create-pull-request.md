フィルタリングの実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストはすべて 1 つのブランチに保存されています。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを管理させます。

> [!NOTE]
> 通常は機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分割します。ワークショップに集中できるよう、フィルタリングと品質のワークフロー全体を 1 つのセッションとブランチにまとめ、この PR に含めています。

このレッスンでは、次のことを行います。

- Agent Merge と、マージ ライフサイクルを自動化する方法を学びます。
- 機能 PR 全体と検証の根拠を確認します。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルタリングのワークフローを通じて、Copilot で機能の計画、実装、検証を行いました。Tailspin Toys では、マージの許可を開発者の管理下に置きながら、PR の残りの作業を自動化します。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み込み、継続的インテグレーション (CI) チェックの失敗を修正し、レビュー コメントに対応し、必要に応じてリベースするなど、マージを妨げている問題を解決します。その後、GitHub が許可した時点でマージします。バックグラウンドで実行され、アプリを再起動しても継続し、PR がマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge に任せることもできますが、コードの編集やマージには明示的な許可が必要です。マージ権限を与える前に、許可する操作と作業内容をレビューします。

## Agent Merge で PR を管理する

コードの作成とレビューが終わったら、Agent Merge に PR のプロセスを管理させます。

1. エージェント ピッカーで **Default agent** を選びます。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンの選択だけでは開始されません。

Agent Merge が開始され、次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連する issue を参照します。
- リベースを行うか、ターゲット ブランチとのマージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- 他の開発者または Copilot code review からのフィードバックを監視し、コメントを解決するために変更します。
- すべて成功した後、必要に応じて PR を自動的にマージします。

すべての条件が満たされた後に Agent Merge が PR をマージするようにします。

5. マージを許可する前に、PR の差分と検証の根拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** にチェックが付いていることを確認します。
8. 次のプロンプトでエージェントに明示的にマージを依頼します。

   ```plaintext
   Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
   ```

9. 進行状況を確認し、報告されたブロッカーに対処します。続行前に PR の状態が **Merged** であることを確認します。マージ権限が有効であることやエージェントが実行中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行する前にブロッカーを解消してください。
