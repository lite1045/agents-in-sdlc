Copilot をエージェント モードで使うと、コードベースを調査し、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って会話を案内できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントに追加の指示を送り、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードの切り替えも追加してほしいと依頼されました。会話を最初からやり直すのではなく、既存のセッションを案内して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** 操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部にある **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用 (ターミナル コマンドの実行など) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するのは、内容を確認して問題ないコマンドだけにしてください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライト モードを追加するようエージェントを案内する

ハイ コントラスト モードの実装が終わったら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けることで、エージェントは前の作業、変更したコンポーネント、使用したスタイル、設定した local storage のパターンを保持します。

1. Copilot Chat の入力欄に次のプロンプトを送ります。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業を確認し、ライト モードを追加する変更を提案します。
3. 新しい編集を確認し、ハイ コントラスト モードと同じように各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止して、明確な追加プロンプトを送ります。

> [!TIP]
> 進行中のセッションを案内する方が、最初からやり直すより早く済みます。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」と調整したり、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」と方向を修正したり、「両方の切り替えにキーボード ショートカットも追加する」と範囲を広げたりできます。

## 変更されたファイルを確認する

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指定した Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保持などが反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視して案内しました。ファイルの編集を確認して承認または取り消し、コンテキストを保ったまま追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または取り消す。
- 進行中のセッションに追加プロンプトを送って案内する。
